CAPABILITY ANALYSIS - DATA SOURCES AND DATABASE TABLES
========================================================

Prepared for: Production / Database team
Purpose: List every table used by the project, so the data can be
connected from the live database instead of CSV exports.


1. IMPORTANT SUMMARY
--------------------

The current web application does NOT connect to a database.

It reads two CSV files and creates four derived CSV files.

  Source CSV files read by the app ............ 2
  Derived CSV files created by the app ........ 4
  Database tables needed to rebuild source 1 .. 9

The main source file (final_revised.csv) is a flat export that was
built in the original project by joining nine database tables.

To run on live data, the database team must either:

  Option A (no code change - recommended first step)
    Create a database view/query that produces the same columns as
    final_revised.csv, export it to CSV on a schedule, and let the
    existing preparation script rebuild the four derived files.

  Option B (requires code change)
    Modify backend/scripts/prepare_dataset.py (or the backend) to
    read directly from the database. This is NOT implemented today.
    It needs a database driver, connection settings, and credentials.


2. FILES THE APPLICATION READS DIRECTLY
---------------------------------------

2.1  final_revised.csv   (~1.3 GB)
     Environment variable: CAPABILITY_RAW_DATA
     Default location: ../Final/final_revised.csv
     Contents: student answers joined with question details and
     correct-answer details. A multiple-choice answer can appear on
     several rows (one per correct choice); the app de-duplicates
     these using the rules in section 7.6.

     Columns actually required by the app:
       user_id
       test_id
       Question_Topic
       Question_Type
       Question_complexity
       questioncomplexity_id
       question_id
       chapter_name
       user_choice_id
       Inserted_Date_Time
       SCQ_choice_id
       MCQ_choice1
       MCQ_choice2
       MCQ_choice3
       MCQ_choice4

     Columns present but NOT used by the app:
       first_name, questiontopic_id, questiontype_id, question,
       choice_name, choice_id, user_answer, user_query, chapter_id,
       Updated_Date_Time

2.2  tbl_users_1.csv   (~260 KB, 1,957 rows)
     Environment variable: CAPABILITY_USERS_DATA
     Default location: ../tables_chosen/tbl_users_1.csv
     Purpose: builds the email -> student ID lookup.

     Columns actually required:
       id
       email
       first_name
       last_name

     WARNING: the full users table also contains password, phone,
     customer_id, and other fields. Do NOT export or share those
     columns. Only the four columns above are needed.


3. FILES THE APPLICATION CREATES (NOT SOURCE DATA)
--------------------------------------------------

These four files are generated by:
  backend/scripts/prepare_dataset.py

They should not be treated as input tables. They can be regenerated
at any time from final_revised.csv.

3.1  question_attempts.csv
     Columns:
       user_id, test_id, test_date, topic, chapter_name,
       question_id, question_type, complexity_id, is_correct

3.2  student_topic_summary.csv
     Columns:
       user_id, topic, test_date, tests_attempted, total_questions,
       total_correct, weighted_score, max_score, score_pct

3.3  student_latest_chapter_summary.csv
     Columns:
       user_id, topic, test_date, chapter_name, tests_attempted,
       total_questions, total_correct, weighted_score, max_score,
       score_pct

3.4  student_email_lookup.csv
     Columns:
       user_id, full_name, email_hmac
     Note: emails are stored only as keyed HMAC-SHA256 digests,
     never as plain text. The key is CAPABILITY_EMAIL_LOOKUP_SECRET
     and must stay the same between preparation and API runtime.


4. DATABASE TABLES NEEDED TO REBUILD final_revised.csv
------------------------------------------------------

Nine tables from the original database (capability_prod) are used.

  #   Table name              Purpose
  --  ----------------------  -------------------------------------
  1   tbl_users               Student identity (id, first_name)
  2   tbl_users_answers       Student answer attempts (main fact)
  3   tbl_questions           Question master data
  4   tbl_answers             Correct answer mapping
  5   tbl_questionchoices     Choice text (answer options)
  6   tbl_questiontopic       Topic names
  7   tbl_questiontype        Question type names
  8   tbl_questioncomplexity  Complexity names
  9   tbl_chapters            Chapter names


4.1  tbl_users
     Required columns:
       id
       first_name
       last_name
       email
     Join: tbl_users.id = tbl_users_answers.user_id
     Do not export: password, phone, customer_id, admin_id, etc.

4.2  tbl_users_answers   (main fact table)
     Required columns:
       user_id
       question_id
       choice_id
       test_id
       user_query
       Inserted_Date_Time
       Updated_Date_Time
     Join keys:
       user_id      -> tbl_users.id
       question_id  -> tbl_questions.id
       choice_id    -> tbl_questionchoices.id
     Note: test_id is available in this table. The app does not use
     tbl_tests to obtain it.

4.3  tbl_questions
     Required columns:
       id
       description
       questiontopic_id
       questiontype_id
       questioncomplexity_id
       chapter_id
     Join keys:
       questiontopic_id      -> tbl_questiontopic.id
       questiontype_id       -> tbl_questiontype.id
       questioncomplexity_id -> tbl_questioncomplexity.id
       chapter_id            -> tbl_chapters.id

4.4  tbl_answers   (correct answers)
     Required columns:
       question_id
       choice_id
     Join: tbl_answers.question_id = tbl_questions.id
           tbl_answers.choice_id  = tbl_questionchoices.id
     One row for a single-choice question.
     Up to four rows for a multiple-choice question.

4.5  tbl_questionchoices   (answer option text)
     Required columns:
       id
       name
       question_id
     Join:
       id         -> tbl_users_answers.choice_id (student answer)
       id         -> tbl_answers.choice_id        (correct answer)
       question_id-> tbl_questions.id

4.6  tbl_questiontopic
     Required columns:
       id
       name
     Join: id = tbl_questions.questiontopic_id

4.7  tbl_questiontype
     Required columns:
       id
       name
     Join: id = tbl_questions.questiontype_id
     The app only uses type 1 (Single Choice) and type 2 (Multiple
     Choice). Other question types are ignored.

4.8  tbl_questioncomplexity
     Required columns:
       id
       name
     Join: id = tbl_questions.questioncomplexity_id
     Only complexity values 1, 2 and 3 are used:
       1 = Beginner
       2 = Intermediate
       3 = Expert

4.9  tbl_chapters
     Required columns:
       id
       chapter_name
     Join: id = tbl_questions.chapter_id


5. JOIN MAP (how the nine tables connect)
-----------------------------------------

  tbl_users
      id
       |
       | user_id
       v
  tbl_users_answers ---- question_id ----> tbl_questions
       |                                      |    |    |
       | choice_id                            |    |    +--> tbl_chapters
       v                                      |    +-------> tbl_questioncomplexity
  tbl_questionchoices                         +------------> tbl_questiontype
       ^                                      +------------> tbl_questiontopic
       | choice_id
  tbl_answers ---- question_id ----> tbl_questions


6. COLUMN MAPPING: DATABASE -> final_revised.csv
------------------------------------------------

  final_revised.csv column   Comes from
  -------------------------  ------------------------------------------
  user_id                    tbl_users_answers.user_id
  test_id                    tbl_users_answers.test_id
  Question_Topic             tbl_questiontopic.name
  Question_Type              tbl_questiontype.name
  Question_complexity        tbl_questioncomplexity.name
  questioncomplexity_id      tbl_questions.questioncomplexity_id
  question_id                tbl_questions.id
  chapter_name               tbl_chapters.chapter_name
  user_choice_id             tbl_users_answers.choice_id
  Inserted_Date_Time         tbl_users_answers.Inserted_Date_Time

                             pivoted into up to four columns)
  first_name                 tbl_users.first_name (not used by app)


7. RULES THE DATABASE VIEW MUST PRESERVE
----------------------------------------

If a database view is created, it must reproduce these rules exactly,
otherwise the scores will differ from the current application.

  7.1  Only question types 1 (Single Choice) and 2 (Multiple Choice)
       are included. All other question types are excluded.

  7.2  Only questioncomplexity_id values 1, 2 and 3 are included.

  7.3  user_id must be numeric and greater than zero.

  7.4  question_id must not be null.

  7.5  Inserted_Date_Time must be a valid timestamp.

  7.6  If one response appears on several rows, keep only the latest
       answer per:
           user_id + test_id + topic + question_id + calendar day
       The application does this using the timestamp order.

  7.7  Correctness rules:
         - Single choice: correct when the selected choice is one of
           the correct choices (SCQ_choice_id).
         - Multiple choice: correct only when the set of selected
           choices exactly equals the set of correct choices.

  7.8  Chapter name cleanup:
         blank, "nan", "null", "0", "No Chapters added yet",
         "No Chapters added", or "General Chapter"
         becomes "General".

  7.9  Blank topic becomes "Uncategorized".

10. PRIVACY AND SECURITY NOTES
------------------------------

  - Never export password, phone, customer_id, or admin fields.
  - Email addresses are hashed by the app before storage, but the
    source users table still contains plain email addresses. Handle
    it as personal data.
  - Do not commit any CSV data to GitHub. The repository contains
    code only.
  - Transfer data files through an approved secure channel.
  - The web application currently has no login or authorization.
    Do not expose it publicly without adding authentication.
